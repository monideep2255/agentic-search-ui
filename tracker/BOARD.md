# Build board

The index of every phase. Maintained by the `task-tracker` skill. Per-phase tickets live in `tracker/phase_N.M.md`, created when a phase opens.

Build phases and their dependencies come from `requirements/Technical_specification.md` Section 25, which is the source of truth. This board never invents a phase.

Two rows are a stated exception to that line rather than a breach of it, both inserted 2026-08-21 by product-owner decision and logged in `DECISIONS.md`: build phase 4.11, the read-only HTTPS graph query service, and build phase 4.12, the demo deployment. Section 25 does not contain either. 4.11 exists because Section 24 specifies the service in full and says its credential is populated "when the service is built (Section 25 build order)", while Section 25 never assigns it to a phase, so one locked section points at another for something that is not there. 4.12 exists because deployment was implied inside build phase 6.1's "CI and CD gates" line, named as no ticket, and sat behind every other phase, so nothing was demoable to anyone until the entire build finished. Both locked documents stay unedited until the next reconciliation, per `v1-scope-boundary`. This is the same deliberate exception build phase 4.8 set when it was inserted, and 4.10 set when it was pulled forward.
