## What was measured rather than built

- L-01's CAUSE FOUND, and the defect is NO LONGER REPRODUCIBLE on develop. When
  no code template matches a question, the plan-tier model drafts the Cypher
  fresh every run, and two drafts are not equivalent: five runs of one BRCA1
  question returned 100 rows, then 1, then an error, then 2, then 2. Twelve live
  runs on 2026-09-23 found no variance at all, where 2026-09-21 saw 100, then
  12, then 0. Two commits nobody re-measured closed it, `27d68ae` and `2bc8ec0`.
- The 2026-09-21 L-01 report was READ WRONG and is corrected: it read the two
  graph calls in result-emission order when they run concurrently. The call that
  looked stable was never the question's search.
- All eleven graph templates were probed against the live graph. Ten live, one
  dead.
- The graph's `Disease` and `OntologyClass` labels hold source vocabularies and
  identifiers in their `name` field, everywhere. `Gene` and `Article` are
  correct.
- The MeSH resolution costs TWO calls for any number of identifiers, measured
  where the ceiling actually charges. 19 of 20 against a worst cold pass of 17.

## What is NOT fixed, stated plainly

- THE GRAPH HOLDS NO DISEASE NAMES AND NO MESH TERMS. Every `Disease` vertex is
  named after its source vocabulary and every `OntologyClass` after its own
  identifier. Tonight's work stops those being presented as real names and
  resolves the MeSH ones live, but the data itself is a Systems 1 and 2 defect
  in the other repository and `.claude/rules/file-protection.md` forbids fixing
  it here. Known since build phase 2.1 as F-2.1-B07, with a census of all
  200,845 Disease rows taken on 2026-07-31. The constraint has never been
  discovery.
- ITEM 5 ABOVE IS THE HONEST GAP. Removing the dead template stops a search that
  could never work. Whether the question then reaches a live path that CAN
  answer it was not verified end to end overnight. That is the first thing to
  check in the morning.
- Telling the reader when a search was drafted by the model rather than taken
  from a checked template is still open. The data already exists:
  `CypherQueryOutput.template` is None exactly in that case. The trap for
  whoever builds it: the degradation is `ok` to `ok`, never `empty`, so a rule
  keyed on empty-or-failed misses the case that costs the reader their evidence.
- The model's written prose still fails the grounding gate on several question
  shapes, so the code-built table carries the answer. Unchanged tonight.
- `trust_outcome` is unstable: five runs with byte-identical evidence returned
  `flag` four times and `ask` once.

## What the day taught

The night's most useful result was not a feature. Three separate tests passed
for months by agreeing with a constant that was wrong, and the constant also
built the schema prompt handed to the plan-tier model, so the model was being
told the same false thing. None of the three was a vacuous arm; each had real
assertions that would have caught a genuinely broken implementation. They were
rigor pointed at a premise nobody had checked.

The second lesson came from a worker retracting its own conclusion. A fix that
improved five measurements made one file worse, and the confirmation run caught
it failing. Cutting the fix's own cost from 400 steps to 73 turned a 77 percent
margin into 16 percent and made the whole suite faster than it had been all
night. The first version would have shipped as an improvement.
